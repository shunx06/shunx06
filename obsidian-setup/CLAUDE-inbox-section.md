## Inbox 整理ルール（iPhone → Mac）

iPhone の Claude で作った Markdown を `Inbox/` に貼り付け、Mac の Claude Code で整理する運用。
「Inbox を整理して」と言われたら以下に従う。

### 対象
- `Inbox/` 内で frontmatter が `status: inbox` のノート**のみ**。

### 振り分け先
| 内容 | 移動先 | ファイル名 |
|---|---|---|
| 論文メモ（1論文の要約・批判的吟味） | `Papers/` | `筆頭著者姓_年_トピック.md`（例: `Ishida_2026_PAEM_cT1b.md`） |
| 既存プロジェクトに関するもの | `Projects/` の該当サブフォルダ（`直腸癌/`、`筋トレ×消化器内科書籍/` 等）。該当ノートが単体ファイルのみなら `Projects/` 直下 | タイトルそのまま |
| 新規プロジェクト候補 | `Projects/` 直下 | タイトルそのまま |
| 週次の進捗・振り返り | `Progress/` | タイトルそのまま |
| アイデア・雑記・フィジーク関連・その他 | `Ideas/` | タイトルそのまま |
| 判断に迷うもの | `Inbox/` に残す | — |

- 論文メモは `Templates/論文メモ.md`、週次進捗は `Templates/週次進捗.md`、プロジェクトは `Templates/プロジェクト.md` の見出し構成に合わせて整形する（中身がない項目は空欄のまま残す）。
- 論文メモの筆頭著者・年・雑誌名が本文から確定できない場合は推測せず、`Inbox/` に残して要確認として報告する。

### 手順
1. **整形**: 見出し階層（`#` はタイトル1つ）、箇条書き、表を整える。コピペで崩れた記号・余分な空行・チャット由来の前置き/締め（「こちらが〜です」等）を除去する。
2. **内容は削らない・創作しない**: 要約や言い換えで情報を落とさない。事実・数値・文献情報を付け足さない。不明点は `> [!question] 要確認:` callout で残す。
3. **移動・リネーム**: 上表に従う。同名ファイルがあれば上書きせず報告する。
4. **タグ**: `inbox` を外し、既存ノートで使われているタグから選ぶ（新規タグは最小限、作ったら報告）。
5. **リンク**: 関連する既存ノート（`Papers/`・`Projects/` 等）があれば本文末の `## Related` に `[[ノート名]]` を追加する。既存ノート側への追記は**提案のみ**（例: プロジェクトノートの文献リストへの追加案）。
6. **完了処理**: frontmatter を `status: done`、`updated: YYYY-MM-DD` にする。
7. **報告**: 処理したノート（移動先）、Inbox に残したもの、要確認事項、既存ノートへの追記提案を一覧で返す。

### 守ること
- `Inbox/` 以外の既存ノートは、明示的に頼まれない限り**編集・移動・削除しない**。
- ルートの `CLAUDE.md` / `MEMORY.md` / `ERRORS.md` / `Home.md`、`Templates/`、`.obsidian/`、`Papers/attachments/` は触らない。
- ファイルの削除はしない。
- 患者を特定できる情報（氏名・ID・生年月日・詳細な日付と施設の組み合わせ等）を見つけたら、編集せずに報告する。
- iCloud 同期の重複ファイル（`ノート 2.md` 等）を見つけたら、統合せずに報告する。
